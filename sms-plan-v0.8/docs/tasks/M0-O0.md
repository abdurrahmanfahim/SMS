# M0-O0 — রিপো ও অ্যাকাউন্ট সেটআপ

| Workstream | Size | Milestone | Wave | Status |
|---|---|---|---|---|
| WS-OWN (আপনি) | S | M0 | 1 | READY |

**Depends on:** none · **Blocks:** M0-P1, M0-P3

## লক্ষ্য
এজেন্টরা কাজ শুরু করতে পারে এমন একটা রিপোজিটরি আর দরকারি অ্যাকাউন্ট তৈরি করা।

## ধাপ
1. GitHub-এ একটা নতুন প্রাইভেট রিপোজিটরি খুলুন (Munshi-র রিপো থেকে আলাদা, নাম আপনার পছন্দ)। zip-এর ভেতরের `README.md` আর `docs/` ফোল্ডার `main` ব্রাঞ্চে কমিট করুন।
2. GitHub অ্যাকাউন্টে 2FA চালু আছে কি না দেখুন।
3. Supabase-এ অ্যাকাউন্ট খুলে `staging` নামে একটা প্রজেক্ট বানান। রিজিয়ন বাংলাদেশের সবচেয়ে কাছেরটা (সাধারণত সিঙ্গাপুর)। ডেটাবেস পাসওয়ার্ড শুধু পাসওয়ার্ড ম্যানেজারে রাখুন।
4. Netlify অ্যাকাউন্ট ঠিক আছে কি না দেখুন। সাইট বানানো হবে M0-P3-তে, তখন রিপো কানেক্ট করবেন।
5. সব অ্যাকাউন্টে ব্যবসার জন্য আলাদা একটা ইমেইল ব্যবহার করুন, যাতে পরে হাতবদল সহজ হয়।
6. এজেন্টদের সেশন সম্ভব হলে আপনার নিজের কম্পিউটারে, আপনার নিজের git লগইনে চালান। কোনো এজেন্টের আলাদা অ্যাক্সেস লাগলে শুধু এই একটা রিপোর জন্য fine-grained টোকেন বানান (Contents ও Pull requests: read/write, মেয়াদ ৩০ দিন)। টোকেন কখনো চ্যাটে বা এজেন্টকে পেস্ট করবেন না।
7. M0-P1-এর রিপোর্টে CI-এর চেকের নাম পাওয়া গেলে `main` ব্রাঞ্চ প্রটেক্ট করুন: PR ছাড়া পুশ নয়, CI পাস ছাড়া মার্জ নয়।
8. Munshi-র রিপো থেকে backup, compute আর db-এর সোর্স ফাইল (যেমন `src/data/backup.js`, `compute.js`, `db.js`) নতুন রিপোর `docs/samples/munshi/` ফোল্ডারে কপি করুন। শুধু কোড, কোনো ইউজারের ডেটা নয়। M2-D2 আর M2-I1 এগুলো পড়বে।

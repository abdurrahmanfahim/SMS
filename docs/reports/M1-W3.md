## Decisions others depend on

- `DataTable`: server mode when `rowCount` is passed (then sorting, filtering and paging are yours; `useTableState` gives `params` with a 1-based `page`, `pageSize`, `sort`, debounced `search`, non-empty `filters`). `columns` and `data` must be referentially stable (`useMemo`) or every render redoes all row work.
- Form values are strings; the submit handler gets parsed output (numbers, E.164 phones, ISO dates). Error messages are i18n keys with an optional query string, built with `formError()`; any other message shows the generic "invalid" text, so untranslated library text never reaches the screen.
- `FileUpload` takes an `upload` function (`Uploader`); use `createSupabaseXhrUploader` (progress, cancel) or `createSdkUploader`. The storage path is built by the caller. Storage keys stay ASCII; share and download names may keep Bangla letters (`safeFileName(..., { unicode: true })`).
- Share helpers are exported from `apps/web/src/shared/share/`. Pass a `Blob` where you can: browsers only open the share sheet right after a tap.
- Print: wrap printable pages in `PrintLayout`; mark anything that must not print with `NoPrint` or the class `sms-no-print`.

## Known issues and debt

- The REST uploader assumes `POST /storage/v1/object/{bucket}/{path}` with a raw body, which matches the Storage REST API, but it has not been run against a real project.
- `shareFile` cannot tell "the share sheet is missing" from "the tap was used up" and downloads in both cases.
- Headless Chromium in this container reports any non-ASCII download name as "download", so the Bangla file name is only unit-tested.
- Page numbers use CSS page margin boxes (Chromium 131 and later); other browsers print none.
- The hard-coded-text check still misses strings built outside JSX.
- Lab scroll limits depend on the machine and could be flaky on a loaded CI runner.

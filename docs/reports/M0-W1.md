## Decisions others depend on

- Register contract: each feature has `src/features/<name>/register.ts` exporting `routes`, `navItems` and optional `widgets`, and `src/features/<name>/i18n/{bn,en}.json`. Route paths are absolute and start with `/app`, `/platform`, `/parent` or `/auth`.
- i18n key rule: at least three dotted segments, `feature.section.key`. Feature keys must be unique across features; the check enforces it. The `shell.*`, `common.*`, `pwa.*`, `install.*` and `devkit.*` prefixes belong to the shell.
- `@sms/ui` components contain no user-visible text of their own; every label (close, error prefix, loading) is passed in by the caller.
- Numbers use the `bn-BD` grouping (12,34,567) in both languages; digit script follows the language unless overridden.
- Feature routes must be lazy so the initial bundle stays under the budget.

## Known issues and debt

- LCP headroom is thin. Playwright lab run (slow 4G, 4x CPU, 360 px): 1.5 to 2.4 s across runs, budget 2.5 s. Lighthouse (default mobile simulation, performance score 92): LCP 2.9 s, CLS 0, TBT 80 ms, accessibility 100, best practices 100. The main cost is the initial JS (128 KB gzip) plus a render-blocking stylesheet. Follow-up: lazy-load dialog and toast code, and split the initial chunk.
- The font preload was added after a real layout shift (CLS 0.28) appeared when the header wrapped and the font swapped. Preloading two fonts costs bandwidth on slow networks; the 600 weight is not preloaded.
- Hard-coded string check misses strings assembled in TypeScript (for example error messages passed as props from non-JSX code).
- The e2e LCP test depends on machine speed and could be flaky on a loaded CI runner.
- Placeholder icons and the "SMS" name are temporary (D-01).
- Route guards are stubs (M1-P2).
- Dark-mode contrast was checked by axe on the shell and dev kit only, not on every future component state.

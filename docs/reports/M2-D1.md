## Deviations and assumptions

1. **Steps 2–4 were committed together with step 1** (`M2-D1: step 1`), not as separate commits: presets, snapshot helpers and typed errors were written while the core was built. Lint and typecheck were green at every commit.
2. **Ranking-tie fixture** covers only engine values (see criterion 2); the spec §10 property "ranking respects the configured order" is not implemented because ranking is M2-D2.
3. **Units:** marks and points are integer hundredths; percent is stored as `percent_bp` and `average_percent_bp` (hundredths of a percent, 66.5% = `6650`). The spec does not fix the stored representation.
4. **Grade from GPA** uses the *rounded* GPA (what the sheet shows), so a displayed 4.00 never gets grade A- ; subject grades use the exact percent (79.99 is A).
5. **Absent:** an absent counted component counts as 0 and fails the subject; "absent in every counted subject" is implemented as every counted component of every counted subject being absent (`all_absent`), giving outcome `absent` with no GPA or grade.
6. **Optional subject** when `gpa.optional.enabled` is false is treated as compulsory; for `percentage_bands` it is treated as a normal subject. A failed optional subject is listed in `failed_subject_ids` but never fails the student.
7. **Missing marks** with policy `block` fail only that student (`status: "error"`, code `missing_marks`); scheme/exam definition problems fail the whole call. Errors take precedence over `withheld`.
8. **G-001 component full marks** are inferred (as the spec §9 warns); subject totals and points match the sheet.
9. **Lint scope:** the new no-float ESLint rule and scan skip `presets.ts`, because it is configuration data written as in spec §7 (for example `3.5`); the engine converts such numbers by reading their decimal text, never by arithmetic.

## Decisions others depend on

- Output shapes: `SubjectResult` (`result_rows.subjects` entries) and `OverallResult` (`result_rows.totals`), including `exact_total {num, den}` (decimal strings) used by `computeOverall`; see TSDoc in `compute.ts`.
- `computeExam(input)` returns `{ ok: true, value: { engine_version, students[] } }`; students sorted by id, subjects by subject id; `ENGINE_VERSION = 1` goes into snapshot `rules`.
- Snapshot checksum = SHA-256 of `canonicalJson({ rules, rows })` via `snapshotChecksum`; `verifySnapshot` recomputes it.
- Error codes: `invalid_config`, `invalid_input`, `bands_overlap`, `bands_gap`, `band_out_of_range`, `duplicate_id`, `unknown_reference`, `unknown_group_code`, `mark_out_of_range`, `missing_marks`, `no_counted_subjects`, `no_compulsory_subjects`.
- Only plain ESM and Web Crypto are used in `src/` (no `node:` imports); Node APIs appear only in test files.

## Deviations and assumptions
- **Assumption, stated once and applied throughout:** Munshi's actual Tailwind/CSS token values were not shared with this task (only the *direction* — "gold accent, primary colour" — is in `munshi-flow-analysis.md`, with no hex codes). Every color in `design-tokens.json` is this task's own choice in that spirit, not a literal port. Flagged prominently in `design-system.md` §7 and as Request 2 below.
- **Real, caught-and-fixed issue:** the first draft of `border.strong` (in both light and dark themes) failed the 3:1 UI-contrast threshold (2.54:1 light, 2.01:1 light... 2.01:1 dark) when actually computed by the script, despite looking "probably fine" as a mid-gray choice. Both values were darkened/lightened until the script confirmed a pass (4.60:1 light, 3.93:1 dark) — this is exactly why the task requires a script instead of eyeballing, and it caught a real mistake here.
- Deviation: the per-state/anatomy/accessibility/microcopy template (step 2) was applied in full only to the 10 **shared** components; the 9 feature-specific components got a lighter table (purpose, screens, owning workstream, why not shared) instead. Reasoning: shared components in `packages/ui` need this level of detail pinned down now since multiple future tasks build against them; feature-specific components are each owned by exactly one future task, which will need to work out their own detailed anatomy anyway once real requirements are in front of them — writing full detail for those now risked inventing specifics `M1-W4`/`M2-E1`/etc. would just have to revise. Flagged as a partial-criterion note above rather than silently claiming full coverage.
- Assumption: `lucide-react` was named as the icon library (§2 of `design-system.md`) since it's already listed as available in this environment's React library list, matching "boring, widely used tools."
- SolaimanLipi's licence could not be confirmed — two secondary sources disagree (GPL vs. SIL OFL 1.0), and neither is the font's own canonical source. This is flagged as **blocking before shipping** (not blocking this documentation task itself) in `design-system.md` §1 and Requests below.

## Decisions others depend on
- **Token names are a contract**: `color.*`, `typeScale.*`, `spacing.*`, `radius.*`, `elevation.*`, `motion.*`, `zIndex.*`, `breakpoints.*` in `design-tokens.json` map one-to-one to CSS variables in `packages/ui` — renaming either side without updating the other breaks the contract (stated in `design-system.md`'s opening line).
- **Component split** (§4's shared-vs-feature-specific table) determines which workstream builds what — `M1-W3` should build the 10 shared components listed; feature tasks (`M1-A2`, `M2-E1`, `M2-A5`, `M2-C1`, etc.) build their own feature-specific ones per the table.

## Deviations and assumptions

0. **CI is not fully green, for reasons outside this task:** see "Known issues and debt" (checked after the push).
1. **Default template texts are not included** although spec §4 says defaults live in `@sms/domain`; the task steps do not list them. See Requests.
2. **Several waivers on one item** (spec silent): applied in list order, each on the amount still payable; total waived never exceeds the amount.
3. **Which plan items are billed:** `monthly` every month (or only `months`); `term` in every `term-N` period, and in a month period only when listed in `months`; `once` and `per_exam` are billed only when their id is in `includeItemIds` (they have no natural period). Waivers are checked on the invoice `issueDate`. Invoice `dueDate` = earliest item `dueDay` in a month period, clamped to the month length; `null` for terms.
4. **Allocation:** `amount` must be positive; chosen invoices are paid oldest first among themselves; invoices are ordered by due date, then invoice number, then id. Applying existing advance credit is done by calling `allocatePayment` with the earlier payment's unallocated remainder as `amount`.
5. **Aging:** an invoice due today has 0 days past due and goes in `0-30`; not-yet-due amounts are reported separately as `notDue` (the spec lists only the three past-due buckets).
6. **Quiet hours:** the start minute is quiet and the end minute is allowed; equal start and end mean no quiet hours; Asia/Dhaka is treated as a fixed UTC+06:00 offset (no DST).
7. **Dedupe keys:** `absent:<student>:<date>` (spec example), `fee_due:<invoice>:m3` or `:p7` (3 days before, 7 days after the due date), `result:<publication>:<student>`, `notice:<notice>:<guardian>`; parts may not contain `:` or whitespace.
8. **During development** a property test of mine had the half-up bound off by one (`< 5000` instead of `<= 5000` at an exact half poisha); the engine was right (fixtures with exact halves already passed) and the test was corrected.

## Decisions others depend on

- All amounts are `Poisha` (integer); percentages are basis points (0 to 10000).
- Results are discriminated unions: `{ ok: true, ... }` or `{ ok: false, reason, id? }`; `renderTemplate` returns `errors` (a list).
- Types for later tasks: `Waiver`, `PlanItem`, `InvoicePeriod`, `InvoiceLine`, `OpenInvoice`, `AllocationMode`, `DueInvoice`, `SegmentLimits`, `QuietHours`; `periodKey` gives the string stored in `invoices.period` (`2026-10`, `term-1`).
- `renderTemplate` output is NFC and free of hidden and directional characters (Bangla ZWJ/ZWNJ kept); pass its `text` to `countSegments` and store that text in `text_outbox.body`. `countSegments(text, limits?)` returns `{ encoding, characters, units, segments, charsLeft }` (`encoding` maps to `gsm7|ucs2`).
- `nextAllowedSendTime(now, window?)` returns a `Date` in `at`; the caller passes the clock (`now`).

## Task-specific items

- Segment-limit assumptions you made: default limits GSM-7 160 single / 153 concatenated and UCS-2 70 / 67 (spec §5, "verify with the chosen provider"), all overridable through `parseSegmentLimits`; GSM-7 means the GSM 03.38 default alphabet plus its extension table (`^ { } \ [ ] ~ | € form-feed` count 2 septets), any other character makes the whole message UCS-2; UCS-2 units are UTF-16 code units (an emoji is 2); characters are packed greedily so an extension character or a surrogate pair is never split across segments; an empty text is 0 segments; the text is counted exactly as given (call `renderTemplate` first so NFC applies).

## Deviations and assumptions
- Assumption: the task's own §3 "context for the steps" names roles as "institution admin, teacher, accountant, guardian, platform owner," omitting `student` even though `permissions.md` and this task's own §3 "roles" line list `student` too. This document follows the 5-role list for the main flows and raises the `student`-role gap explicitly as open question 1, rather than inventing student-facing screens with no task in `INDEX.md` to build them.
- Assumption: "at most 2 taps" is achieved for several admin/teacher tasks via a proposed "contextual shortcut card" pattern on the home screen (e.g. a "ready to publish" card). This is a UX proposal, not yet validated with users or agreed by the Leader — flagged in the Task-specific items as the least-certain of the three listed decisions.
- Assumption: `docs/spec/fees-and-alerts.md` (M3-L1, already `DONE` per `INDEX.md`) was read as the source for guardian-portal and fee-related placeholder content, even though this task's own file list (§4.4) does not name it — it was the only way to give the M3 placeholders (guardian home, fee screens) any real structural basis instead of guessing from nothing.

The Owner or CI (which likely has full network access) should re-run the exact command from section 6 once to confirm actual rendering; this is noted as a known gap, not hidden.
- Deviation: committed the single file and the report together rather than one commit per step, since all 7 steps landed in one file with no natural per-step commit boundary (matching the pattern already used in M0-R3 for the same reason).

## 3. Project context (so you are never lost)
- Product: a Bangla-first school management system for schools, madrasas and coaching centres in Bangladesh, built so an institution can run everything on a phone. It is a separate paid product; Munshi is a different, free, single-user app.
- Stack: TypeScript (strict), React 19, Vite, Tailwind, shadcn/Radix, Supabase (Postgres, RLS, Edge Functions), pnpm monorepo, Netlify.
- Layout: `apps/web`, `packages/{domain,db,ui,config}`, `supabase/`, `e2e/`, `docs/`.
- Tenancy: one database; every tenant row has `institution_id`; isolation is enforced by Postgres RLS, never by app code.
- Roles: platform owner, institution admin, teacher, accountant, guardian, student.
- Phone-complete: every task must work on a 360 px phone with touch only (Android first, iPhone second).
- Numbers: money in integer poisha; marks in integer hundredths inside calculations; never floating point.
- Language: Bangla first, English second; all user-visible text goes through i18n keys.
- Quality bar: WCAG 2.2 AA, `docs/spec/ux-standard.md`, and the Definition of Done in README section 9.

**Decisions in force for this task (do not reopen them, except any marked "under review"; for those, do not make the choice yourself: use what the task says and note it in the report):**
- D-03 — Language and frontend: TypeScript (strict); React 19 + Vite + Tailwind + shadcn/Radix (same family as Munshi); pnpm monorepo; Netlify hosting unless `M0-P3` finds a reason to change
- D-06 — Offline scope: Online-first PWA. Offline queue only for attendance and marks entry (idempotent, client-generated IDs). No full offline replica in v1
- D-14 — UX standard and process: ISO 9241-210 process (interviews, flows, prototypes, user tests, pilot evaluation); WCAG 2.2 AA; Nielsen heuristics as review checklist; Core Web Vitals targets; `docs/spec/ux-standard.md` is binding

### 5.2 Steps (do them in this order)
After every step: run the fast check (pnpm lint && pnpm typecheck), then commit with the message `M0-W1: step N` and push (`git push`), so the Owner and the Leader can see progress and your last-activity time stays fresh.
If a step shows that the task needs something outside its scope, do not work around it: note it under "Requests" or go to section 10.

**Step 1.** Router with route groups `/auth/*`, `/app/*` (staff), `/platform/*` (platform console), `/parent/*` (guardian). Guards are stubs until M1-P2.

**Step 2.** Feature discovery: the shell loads every `apps/web/src/features/*/register.ts` through `import.meta.glob` (eager). A `register.ts` exports `{ routes, navItems, widgets }`; the shell merges them, so feature tasks never edit shell files. Feature i18n lives in `apps/web/src/features/*/i18n/{bn,en}.json` and is merged by the i18n loader; the CI key check covers those files too.

**Step 3.** Layout: bottom tab bar on mobile, sidebar on desktop. Navigation is data: `NavItem { key, labelKey, icon, path, roles: Role[] }`, filtered by the current role. A dev-only role switcher exercises it.

**Step 4.** `packages/ui`: design tokens (CSS variables) generated one to one from `docs/spec/design-tokens.json`, Tailwind config, shadcn/Radix components (states and accessibility notes per `docs/spec/design-system.md`): Button, Input, Select, Dialog, Sheet, Toast, Card, Badge, Skeleton, EmptyState, ErrorState, ConfirmDialog. Dev-only `/dev/kit` route to view them.

**Step 5.** i18n: Bangla default, English second, keys named `feature.section.key`, language switcher persisted, CI script that fails on keys missing in either language, lint or grep check for hard-coded strings in components.

**Step 6.** Bangla web font(s): self-hosted subset, permissive licence, documented in `docs/decisions/0004-fonts.md`, with a fallback stack. Numbers and dates are formatted through `Intl` (`bn-BD`, Bangla numbering system), not hand-made digit maps.

**Step 7.** PWA baseline: `vite-plugin-pwa`, manifest with placeholder name and icons, app-shell caching, an update-available prompt, an offline fallback page.

**Step 8.** Patterns: skeleton loading, empty state, error boundary, toasts, one sample form layout.

**Step 9.** Phone essentials: viewport meta with `interactive-widget=resizes-content` plus a visual-viewport fallback so the focused field and its action bar stay visible with the on-screen keyboard open (test on Android Chrome and iOS Safari); safe-area insets; a sticky bottom action bar component that sits above the keyboard; a Bangla install guide for Android and iPhone (Add to Home Screen) and an install prompt where the browser supports it.

**Step 10.** UX rules from `docs/spec/ux-standard.md` built into the shell: a Help entry in the same place on every page (WCAG 3.2.6), scroll padding so sticky bars never hide the focused element (2.4.11), a skip link, visible focus styles, and reorder controls that never depend on dragging alone (2.5.7).

**Step 11.** `docs/decisions/0005-performance-budget.md` with numeric budgets (start: initial JS for the shell route at most 200 KB gzip, CSS at most 40 KB gzip, lab LCP at most 2.5 s on a slow-4G, 4x CPU throttled profile as a proxy for the Core Web Vitals field targets at the 75th percentile: LCP at most 2.5 s, INP at most 200 ms, CLS at most 0.1; tap targets at least 44 px) and a CI check that fails when the bundle budget is exceeded.

**Context for the steps:** Mobile first (360 px), Bangla first, low-end Android on slow networks. Feature code arrives later under `apps/web/src/features/**`. Munshi's look is a reference, not a constraint.
